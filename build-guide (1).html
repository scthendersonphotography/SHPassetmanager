Section 01

Overview

The SHP Asset Manager system is built around several complementary hardware units. You only need to build the devices that apply to your workflow — most users build one transmitter and one or two receivers.

Laser Eye V2 TX V2
ESP32-based LiDAR transmitter. Detects subject distance and fires camera triggers over BLE or ESP-NOW. The primary triggering device for wildlife and nature photography.
Cable Trigger
ESP32-based servo controller for physical cable release operation. Used when a wired shutter connection is needed. Pairs with the Cable Trigger tab in the app.
Mini RX V2 V2
Compact ESP32 receiver. Accepts ESP-NOW trigger packets from the Laser Eye V2 TX and drives a camera shutter output. Mounts close to the camera.
Full ESP32 RX V2 V2
Full-size ESP32 dev-board receiver. Functionally identical to the Mini RX V2 — use this if you prefer a standard 38-pin form factor.
Pi TX PI
Raspberry Pi–based transmitter. Supports TF-Luna LiDAR, Pi Camera, USB webcam, DSLR via gPhoto2, Google Drive upload, time-lapse, astronomy, and live preview. Control it from the native PI TX app tab or the browser panel.
ESP-NOW UART Bridge
Attaches to the Pi TX's UART port and relays ESP-NOW trigger packets to Mini RX / Full RX receivers in the field — extends Pi TX range wirelessly.

The SHP Asset Manager mobile app is the control surface for the ESP32 units and Pi TX. It is software rather than a hardware unit, so its controls are described in the user manuals.

This guide covers assembly and wiring only. For firmware flashing and software installation see the Firmware & Software Install Guide. For app usage see the Lazer Eye User Manual.

Trigger Output — Isolation Circuit

Never connect GPIO directly to your camera's shutter port without isolation. A wiring mistake could damage the camera. Use Option A only for quick bench testing.

Option A — Direct (bench testing only): GPIO 4 → camera shutter tip. ESP32 GND → camera sleeve (GND). GPIO 4 pulls LOW to trigger, short-circuiting the tip to GND. Set invertTrig = 0 in firmware.

Option B — NPN transistor (recommended):

  • GPIO 4 → 1 kΩ → Base of 2N3904
  • Collector → camera shutter tip
  • Emitter → camera shutter GND (sleeve)
  • Camera GND and ESP32 GND must share a common reference
  • Set invertTrig = 1 in the app (trigger fires LOW)
Option B — NPN Transistor Isolation Circuit (GPIO 4 → Camera)

Option C — PC817 optocoupler (full isolation):

  • GPIO 4 → 330 Ω → PC817 anode (pin 1)
  • PC817 cathode (pin 2) → GND
  • PC817 collector (pin 4) → camera shutter tip
  • PC817 emitter (pin 3) → camera shutter GND
  • Camera side is fully isolated — no shared ground required
  • Set invertTrig = 1 in the app

Wire the WAKE_OUT (GPIO 12 or GPIO 16) to the camera's AF / focus ring using the same circuit.

Section 04

Mini RX V2 V2

The Mini RX V2 runs on a compact ESP32 module and listens for ESP-NOW trigger packets from the Laser Eye V2 TX. It drives camera shutter and wake outputs through a transistor or optocoupler isolation circuit.

The firmware supports both original ESP32 DevKit Mini (non-S2) and ESP32-S2 Mini boards. The S2 variant uses a different battery ADC pin and exposes alternate output pins on the odd-column header for a cleaner single-connector build.

Section 06

Pi TX PI

The Pi TX turns a Raspberry Pi into a full-featured camera trigger and upload station. It supports TF-Luna LiDAR triggering, Pi Camera CSI, USB webcam, DSLR via gPhoto2, live preview, time-lapse, astronomical scheduling, and automatic upload to Google Drive. All control happens through the phone app or browser panel — no monitor or keyboard is needed in the field.

Recommended Raspberry Pi Models

  • Raspberry Pi 4 Model B — best performance; handles simultaneous LiDAR + camera + upload.
  • Raspberry Pi 3 Model B+ — supported for standard trigger and camera workflows.
  • Raspberry Pi 5 — supported and best for heavier simultaneous camera and upload workloads.

The installer is tested on Raspberry Pi OS Lite (Bookworm, 64-bit) with Pi 3B+, Pi 4, and Pi 5. Other models may work but are not part of the current tested target.

Shutter Output — Trigger Wiring Options

Do not connect the Pi's 3.3 V GPIO directly to a camera shutter without isolation. The Pi GPIO cannot source or sink significant current safely, and a wiring error can damage the Pi.

Option A — Direct dry-contact (bench testing only): GPIO 17 → camera shutter tip. Pi GND → camera sleeve (GND). GPIO 17 pulls LOW to fire, short-circuiting tip to GND and closing the shutter contact. No transistor. Set invertTrig = 0 (default).

Option B — NPN transistor (recommended):

  • GPIO 17 → 1 kΩ → 2N3904 Base
  • Collector → camera shutter tip
  • Emitter → camera GND (sleeve)
  • Pi GND and camera GND must share a common reference
  • Set invertTrig = 1 in the app
Option B — NPN Transistor Isolation Circuit (GPIO 17 → Camera)

Option C — PC817 optocoupler (full isolation):

  • GPIO 17 → 330 Ω → PC817 anode (pin 1)
  • PC817 cathode (pin 2) → Pi GND
  • PC817 collector (pin 4) → camera shutter tip
  • PC817 emitter (pin 3) → camera shutter GND (sleeve)
  • Set invertTrig = 1 in the app

Hot-mode trigger (trigMode = 1): GPIO 17 drives 3.3 V directly to the camera tip. Use only for cameras that accept an active-HIGH signal on the shutter port — verify your camera's spec before wiring.

Wire GPIO 27 (WAKE/AF) using the same isolation circuit as the shutter output.

raspi-config Settings

The install script runs raspi-config non-interactively for the following two settings. If you need to verify them manually:

  • Interface Options → I²C: Enable (required for TF-Luna LiDAR).
  • Interface Options → Serial Port → Login shell over serial: Disable. Hardware serial port: Enable. (Required for UART Bridge.)

Pi Camera support does not require a separate raspi-config camera step on modern Raspberry Pi OS (Bookworm). The install script installs python3-picamera2 and libcamera-apps via apt, which is sufficient for both Pi Camera v2 and Pi Camera 3 CSI modules.

Local-first WiFi network

The installer creates a secured NetworkManager hotspot that stays available for local control, even when the Pi has no internet. The SSID begins with PI_TX_, the Pi uses 10.42.0.1, and the generated password is printed by the installer and stored root-only on the Pi. Ethernet or a second WiFi adapter can optionally provide upstream internet without taking the built-in WiFi adapter away from the hotspot.

Do not connect the Pi's GPIO directly to a camera shutter without the documented isolation circuit. The direct dry-contact option is for bench testing only.

Section 07

ESP-NOW UART Bridge

The ESP-NOW UART Bridge connects to the Pi TX's hardware UART port and re-transmits trigger packets over ESP-NOW to any paired Mini RX V2 or Full RX V2 receivers in the field. It lets the Pi TX drive wireless receivers without any dedicated ESP-NOW radio on the Pi itself.

Supported ESP32 Boards

  • ESP32-DevKit-C / WROOM-32 — plug-and-play, no pin remapping needed.
  • ESP32-C3 Mini — change BRIDGE_UART_RX to GPIO 6 and BRIDGE_UART_TX to GPIO 7 in the firmware before flashing.
  • ESP32-S3 Mini — change BRIDGE_UART_RX to GPIO 4 and BRIDGE_UART_TX to GPIO 5 before flashing.

Section 08

Troubleshooting

Common hardware assembly problems and their fixes. Firmware-related issues are covered in the Install Guide §12.

ESP-NOW Pairing

Laser Eye V2 TX fires but the Mini RX V2 / Full RX V2 does not respond — no trigger output on the receiver
Confirm the receiver's STA MAC address was entered correctly during pairing in the app (format AA:BB:CC:DD:EE:FF — all uppercase, colon-separated). The MAC is printed to Serial Monitor at 115200 baud on every boot. If the MAC was entered correctly, clear the pairing on both sides: hold the receiver's BOOT button (GPIO 0) LOW for 3 seconds on power-on until the LED blinks rapidly, then re-pair in the app. Ensure both devices are within reliable ESP-NOW radio range (open air: <200 m; walls and obstructions reduce this significantly).
Mini RX V2 shows as paired in the app but stops receiving triggers after a power cycle
The pairing is stored in flash (Preferences) on the receiver. If the receiver has been reflashed since pairing, the stored peer MAC is erased and you must re-pair. After any firmware flash, always re-pair the receiver from the app before use.

Trigger Output

Trigger output not firing the camera — shutter does not activate even though the trigger LED blinks
Check the invertTrig setting in the app — the correct value depends on your wiring option. Direct connection (Option A): set invertTrig = 0. NPN transistor (Option B) or PC817 optocoupler (Option C): set invertTrig = 1. Also verify your camera's shutter port is 2.5 mm TRS (most DSLRs and mirrorless) and that tip and sleeve assignments match your wiring — a reversed cable will not fire the shutter.
Trigger fires the camera but the camera body powers off or behaves erratically
The camera GND (sleeve) and ESP32 / Pi GND are not sharing a common reference, causing a floating or unexpected voltage on the shutter port. Ensure the shared ground wire is connected as shown in the NPN transistor circuit diagram in §02 or §06. If using Option A (direct), ensure ESP32 GND is tied to the camera's shutter sleeve directly.
WAKE / AF output does not wake the camera before the shutter fires
Wire the WAKE_OUT pin (GPIO 12 on Laser Eye TX; GPIO 27 on Pi TX) to the camera's ring contact (2.5 mm TRS: ring = AF/wake; tip = shutter). Use the same isolation circuit as the shutter output. The firmware pulses WAKE_OUT before TRIGGER_OUT by the wake-up delay configured in the app — confirm this delay is non-zero.

Battery Percentage

Battery percentage reads 0 %, stuck at 100 %, or wildly inaccurate
Verify the voltage divider is wired correctly: Battery+ → R1 → midpoint → R2 → GND, with the midpoint tapped to the ADC input pin (GPIO 34 on full-size boards; GPIO 9 on ESP32-S2 Mini). Measure the midpoint voltage with a multimeter at a known battery charge level and confirm it matches the expected value from the divider formula. Also verify the resistor values match the values expected by the firmware's BATT_SCALE constant — a wrong resistor value (e.g. 10 kΩ instead of 100 kΩ) will produce consistently wrong readings.
ESP32-S2 Mini always reads 0 % battery regardless of charge level
The S2 Mini uses a switched ADC circuit controlled by GPIO 12 (BATT_EN_PIN). Confirm GPIO 12 is wired to the 10 kΩ base resistor as shown in the S2 Mini switched ADC diagram in §04. If GPIO 12 is unconnected, the transistor gate never opens and the ADC reads nothing. Also ensure you selected ESP32-S2 Dev Module as the board in Arduino IDE — compiling for a standard ESP32 board will use the wrong ADC pin assignments.

TF-Luna LiDAR

TF-Luna not detected on I²C — Serial Monitor shows repeated "TF-Luna init failed" or distance always reads 0 or –1
First confirm the TF-Luna is in I²C mode — units shipped in UART mode will not respond on I²C. Use the TF-Luna configuration tool (TFMini Plus Config Tool, Windows only) or short the UART/I²C mode selection pad on the sensor PCB to switch it. Next check wiring: SDA → GPIO 21, SCL → GPIO 22 for Laser Eye TX; SDA → Pi GPIO 2 (Pin 3), SCL → Pi GPIO 3 (Pin 5) for Pi TX. The ESP32 uses internal pull-ups on I²C; the Pi may need external 4.7 kΩ pull-ups if the cable run is long (>30 cm). Finally confirm power: the TF-Luna draws up to 130 mA at 5 V — ensure the supply can deliver this alongside the rest of the circuit.
TF-Luna reports valid distance but readings are noisy or jump erratically
Strong ambient IR light (direct sunlight or nearby IR sources) saturates the TF-Luna's receiver and produces noisy readings. Shade the sensor aperture or reduce the frame rate in firmware to give the sensor longer integration time. Also check that the I²C cable is away from the servo signal wire (Cable Trigger) or any PWM lines — coupling noise can corrupt readings.
