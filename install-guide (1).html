Section 02

Arduino IDE & Board Package

All ESP32 firmware in this project is written for the Arduino IDE with the official Espressif ESP32 board package. Arduino IDE 2.x is recommended.

Install Arduino IDE

  1. Download Arduino IDE 2.x from arduino.cc/en/software. Choose the installer for your operating system (Windows, macOS, or Linux).
  2. Run the installer and follow the on-screen prompts. Accept the default install path.
  3. Launch Arduino IDE. On first run, allow any firewall prompts it requests.

Add the ESP32 Board Package

  1. Open File → Preferences (macOS: Arduino IDE → Settings).
  2. In the Additional boards manager URLs field, paste this URL: 
    https://raw.githubusercontent.com/espressif/arduino-esp32/gh-pages/package_esp32_index.json
    If there are already URLs in the field, add a comma then the new URL on the same line.
  3. Click OK to close Preferences.
  4. Open Tools → Board → Boards Manager.
  5. Search for esp32. Select the entry published by Espressif Systems.
  6. Click Install. The download is several hundred MB — allow a few minutes.
  7. When the status bar shows "Installed", close the Boards Manager.

The board package must be version 2.0.0 or later. Earlier versions lack full NimBLE and AsyncTCP support.

USB Driver

Most ESP32 dev boards use a CH340 or CP210x USB-to-UART chip. If your computer does not recognise the board when plugged in, install the driver for your chip:

  • CH340 / CH341: wch.cn/en/download — "CH341SER" driver.
  • CP2102 / CP2104: silabs.com — "CP210x USB to UART Bridge VCP Drivers".

After driver install, replug the board. It should appear as a new port in Tools → Port.

The Full ESP32 RX V2 firmware uses only the ESP32 core built-ins (esp_now.h, WiFi.h, Preferences.h). No additional library installs are needed for that device.

TM1637 is marked Required for the Cable Trigger because the firmware unconditionally includes <TM1637Display.h> at compile time — the sketch will not compile without it. The TM1637 display module must be wired to the board.

Installing Libraries

  1. Open Tools → Manage Libraries.
  2. Search by the library name (e.g. "NimBLE-Arduino"). Select the correct publisher and click Install. Accept any dependency prompts.
  3. Repeat for each required library in the table above.

ESPAsyncWebServer — Alternative Source

If the me-no-dev version does not appear in Library Manager, use the ESP32Async fork, which is more actively maintained:

  1. In Library Manager, search ESP Async WebServer. Select the entry published by ESP32Async (or mathieucarbou).
  2. Install it along with the AsyncTCP dependency.

Both forks are API-compatible with this firmware. Use whichever appears in your Library Manager.

Flash Laser Eye V2 TX V2

Board Settings

PortSelect the COM / /dev/tty port that appears when you plug in the board

Flash Steps

  1. Open the firmware sketch: File → Open → navigate to firmware/laser_eye_v2_firmware.ino.
  2. Connect the Laser Eye V2 TX board to your computer via USB.
  3. Select the board and port under Tools.
  4. Click Sketch → Upload (or the → arrow button). The IDE compiles then flashes.
  5. Watch the output panel. When you see "Leaving... Hard resetting via RTS pin", flashing is complete.
  6. Open Tools → Serial Monitor at 115200 baud. Confirm the boot message shows the firmware version and "LR_TX_V2" device name.

If the board doesn't enter flash mode automatically, hold the BOOT button on the ESP32 while clicking Upload, then release it once the IDE shows "Connecting..."

  • ESPAsyncWebServer
  • AsyncTCP
  • TFLI2C

Flash Mini RX V2 V2

Select the board type that matches your physical hardware — original ESP32 Mini or ESP32-S2 Mini. The firmware auto-detects S2 at compile time and activates the alternate pin set and S2 battery ADC circuit.

Board Settings — ESP32-S2 Mini

SettingValue
BoardESP32-S2 Dev Module (or your board's exact name)
Upload Speed921600
Partition SchemeDefault
PortSelect your USB port

Flash Steps

  1. Open firmware/lr-mini-rx-v2/lr_mini_rx_v2_firmware.ino.
  2. Select the correct board (original or S2) and port under Tools.
  3. Click Upload.
  4. Open Serial Monitor at 115200 baud. At boot, the Mini prints its STA MAC address — note this down, you will need it for pairing in the app.
  5. Confirm the device reports firmware version and "LR_MINI_RX_V2".

Pairing the Mini RX V2 with the Laser Eye V2 TX

  1. Note the STA MAC address shown in the Serial Monitor at boot (format: AA:BB:CC:DD:EE:FF).
  2. In the SHP Asset Manager app, open the LiDAR tab → ESP-NOW → tap Pair.
  3. Enter the Mini's STA MAC when prompted and confirm.
  4. The Mini will auto-pair on receiving the first trigger packet from the Laser Eye V2 TX and will send back its device type.

To clear a stored pairing, hold GPIO 0 (the boot button) LOW during power-on for 3 seconds. The status LED will blink rapidly to confirm the pairing was cleared.

Required Libraries (reminder)

  • ESPAsyncWebServer
  • AsyncTCP

Section 09

Pi TX Software Install PI

The Pi TX daemon, web UI, and all dependencies are installed by a single script. The script handles apt packages, pip packages, raspi-config settings (I²C and UART only), a persistent local WiFi hotspot, the systemd service, mDNS (Avahi), and the UI build. Pi Camera support is provided by the installed apt packages — no separate raspi-config camera step is needed on modern Raspberry Pi OS.

Prerequisites

  • Raspberry Pi running Raspberry Pi OS Lite (Bookworm, 64-bit) — the installer is tested on Pi 3B+, Pi 4, and Pi 5. Bullseye or other images may require additional changes and are not the current tested target.
  • The Pi is connected to the internet (Ethernet or WiFi) before running install so it can download system and Python packages. Internet is not required for local camera control after installation.
  • SSH or keyboard access to the Pi's terminal.
  • The SHP Asset Manager repository cloned onto the Pi.

Install Steps

  1. Clone the repository onto the Pi (or copy the project folder via SCP/USB): 
    git clone <repository-url>
cd <repository-folder>
  2. Navigate into the directory that contains install.sh, main.py, and requirements.txt. In the development monorepo: 
    cd artifacts/pi-tx
    If you cloned the published standalone Pi TX repository, use cd SHPassetmanager instead because those files are at the repository root.
  3. Make the install script executable and run it with sudo: 
    chmod +x install.sh
sudo ./install.sh
    The script will take several minutes to complete — it downloads apt packages including picamera2 and opencv, installs Python dependencies, and builds the web UI.
  4. When the script finishes, reboot the Pi: 
    sudo reboot

Connect locally without internet

  1. After reboot, join the WiFi network whose name starts with PI_TX_. The installer prints the generated password; rerunning the installer preserves it unless you explicitly supply a replacement.
  2. Open the phone app's PI TX tab and connect. The app checks the fixed local address 10.42.0.1 first.
  3. For browser control, open http://10.42.0.1 from a device joined to the Pi TX hotspot.
  4. The phone may warn that this WiFi network has no internet. Stay connected: local triggering, camera control, preview, time-lapse, and schedules do not require internet.

Optional internet can be supplied through Ethernet or a second USB WiFi adapter. The built-in WiFi adapter remains dedicated to the Pi TX hotspot.

Verify the Service is Running

  1. After reboot, check the systemd service status: 
    systemctl status pi-tx
    The output should show active (running).
  2. Tail the live log to watch for errors: 
    journalctl -u pi-tx -f
    Press Ctrl+C to exit the log view.
  3. From another device on the same network, open a browser and navigate to: 
    http://pi-tx.local
    The Pi TX web UI should load. This confirms mDNS, the daemon, and the web server are all working. When using the Pi TX hotspot instead, open http://10.42.0.1.

If pi-tx.local does not resolve, try the Pi's IP address directly. Find the IP with hostname -I run on the Pi. mDNS resolution may take a minute or two after first boot.

Google Drive Setup

To enable automatic upload of captured photos to Google Drive, the Pi TX must be authorized with your Google account. This is done through the app after installation:

  1. Open the SHP Asset Manager app and connect to the Pi TX via the Browser Panel.
  2. Navigate to Upload → Google Drive and tap Authorize.
  3. The Pi will generate a Google authorization URL. Open it on any device, sign in, and grant access.
  4. Authorization tokens are stored securely on the Pi and persist across reboots.

Google Drive upload requires the Pi to have internet access at the time of authorization. Field sessions without internet still capture locally; uploads happen when connectivity is restored.

Section 10

App Install

The SHP Asset Manager app is a React Native / Expo application that runs on iOS and Android. It communicates with the Laser Eye V2 TX and Cable Trigger over BLE and WiFi, and with the Pi TX via its web UI.

Development Build (Expo Go)

  1. Install the Expo Go app on your phone from the App Store (iOS) or Google Play (Android).
  2. On your development computer, install Node.js (18 or later) and run: 
    npm install -g expo-cli
  3. In the project root, install dependencies: 
    pnpm install
  4. Start the Expo dev server for the app: 
    pnpm --filter @workspace/cable-trigger run dev
  5. Scan the QR code shown in the terminal with the Expo Go app on your phone.

Expo Go runs a JavaScript bundle from your dev machine. The phone and computer must be on the same WiFi network.

Production Build

For a standalone APK or IPA that does not require the Expo Go wrapper, use EAS Build. Refer to the Expo documentation for EAS Build setup — this is outside the scope of this install guide.

BLE device scanning requires the app to run in a production or development build (not in Expo Go's default web mode). Ensure BLE permissions are granted when prompted on first launch.

Section 11

OTA Firmware Updates

The Laser Eye V2 TX, Cable Trigger, Mini RX V2, and ESP-NOW UART Bridge all support over-the-air firmware updates. The update path and access controls differ by device — read the relevant subsection before updating.

If power is lost or the update is interrupted mid-transfer, the firmware partition may be left in a corrupt state. The ESP32 does not automatically roll back to the previous firmware in these builds. Recovery requires USB reflashing via Arduino IDE (see the flashing sections above for board settings).

Generating the .bin File

All OTA methods require a compiled .bin file. To produce one:

  1. Open the firmware sketch in Arduino IDE with the correct board and settings (same as the initial flash).
  2. Choose Sketch → Export Compiled Binary. Arduino IDE writes a .bin file into the sketch folder.
  3. Transfer the .bin to your phone or computer as needed for the update method below.

Laser Eye V2 TX — OTA via BLE (App)

The Laser Eye V2 TX receives firmware updates over the BLE connection. No WiFi or HTTP endpoint is involved in the normal app-driven flow.

  1. Connect to the Laser Eye V2 TX in the app via BLE.
  2. Navigate to the device settings panel and tap Firmware Update.
  3. Select the .bin file. The app streams the binary over BLE in base64-encoded chunks.
  4. The device reboots automatically when the transfer completes.

The Laser Eye V2 TX also registers an HTTP /update endpoint on its WiFi AP. This endpoint has no additional access control beyond network access — only use it while directly connected to the device's own AP, never on an untrusted shared network.

Cable Trigger — OTA via BLE (App)

The Cable Trigger uses the same BLE-based OTA flow as the Laser Eye V2 TX. Connect in the app, navigate to Firmware Update, and select the .bin.

Like the Laser Eye TX, the Cable Trigger also has an HTTP /update endpoint with no token protection. Use it only while connected to the device's own AP.

Mini RX V2 — OTA via HTTP

The Mini RX V2 enters OTA mode when its BOOT button (GPIO 0) is held for 3 seconds while the device is already running. It then raises a WiFi AP and serves firmware uploads over HTTP.

  1. With the Mini RX V2 powered on and running normally, hold the BOOT button (GPIO 0) for 3 seconds. The status LED will fast-blink to confirm OTA mode is active.
  2. Connect your phone or computer to the LR-MINI-RX-OTA WiFi network. The password is lrmini123.
  3. Open a browser and navigate to http://192.168.4.1/update.
  4. Select the .bin file and upload. The device reboots when complete.

The Mini RX AP password lrmini123 is a fixed value shared by all Mini RX V2 units — it provides only basic access control. Keep OTA updates to situations where you are the only device connected to the Mini's AP. Do not perform updates on shared or public networks.

ESP-NOW UART Bridge — OTA via Token-Gated HTTP

The Bridge has the strongest OTA security of all devices. The Pi daemon generates a random per-session token, sends it to the Bridge over UART, and the app receives it through the Pi's authenticated channel. The Bridge raises a temporary WiFi AP using the token as both the WPA2 password and the required URL query parameter.

  1. In the app, navigate to the Bridge settings and tap Update Bridge Firmware.
  2. The app coordinates with the Pi daemon to obtain the session token and switch the Bridge into OTA mode.
  3. Connect to the LR-BRIDGE-OTA WiFi AP (password = session token, shown in the app).
  4. The app uploads the .bin to http://192.168.4.1/update?token=<token>. Requests without the correct token receive a 403 response.
  5. The Bridge reboots and reconnects to the Pi UART when complete.

Pi TX Software Updates

The Pi TX daemon is updated by pulling the latest code and running the install script again:

cd <directory-containing-pi-tx-files>
git pull
sudo ./install.sh
sudo systemctl restart pi-tx

A full reboot is not required for daemon-only updates — systemctl restart pi-tx is sufficient unless the install script specifically prompts for a reboot.

Section 12

Troubleshooting

Common problems encountered during firmware flashing and software installation, with their causes and fixes.

Arduino IDE — Board & Port

Board not detected — no port appears in Tools → Port after plugging in the ESP32
Install the USB-to-UART driver for your board's chip (CH340 / CH341 or CP2102 / CP2104). See §02 USB Driver. After driver install, replug the board and wait a few seconds. On Windows, check Device Manager for a yellow-flagged "Unknown device" to identify the chip.
Upload stuck at Connecting... with dots repeating indefinitely
The ESP32 is not entering flash mode. Hold the BOOT (IO0) button on the board, click Upload, and release the button once the IDE output shows "Connecting..." — the upload should begin immediately. Some boards also require a brief press of the EN/RESET button while BOOT is held. After first successful upload, subsequent uploads usually auto-enter flash mode.
Port disappears mid-upload or upload fails with a serial timeout error
Try a different USB cable — many USB cables are charge-only and lack the data wires needed for serial communication. Reduce Upload Speed to 460800 in Tools if errors persist on the cable you have.

Arduino IDE — Compilation

fatal error: NimBLEDevice.h: No such file or directory (or similar for any library header)
The required library is not installed. Open Tools → Manage Libraries, search for the library name, and install it. Ensure you installed the correct publisher — see the library table in §03. If the library was installed, restart Arduino IDE after installation; the IDE occasionally fails to index a newly installed library until restarted.
Sketch compiles but shows "Sketch too large" or flash size overflow error
Change the Partition Scheme in Tools to Huge APP (3 MB No OTA / 1 MB SPIFFS). This allocates more flash to the application at the cost of OTA update capability. If OTA must be retained, use Minimal SPIFFS (1.9 MB APP with OTA).
Compilation error referencing TM1637Display.h when building a device other than the Cable Trigger
You have the wrong sketch open. Confirm the filename in the Arduino IDE tab matches the firmware listed in §01 for the device you are building. Do not mix firmware files between devices.

Pi TX — Service & Network

Pi TX service fails to start — systemctl status pi-tx shows failed or activating
Run journalctl -u pi-tx -n 60 to read the last 60 log lines and find the specific error. Common causes: (1) Python dependency missing — re-run sudo ./install.sh to reinstall. (2) Port already in use — check for another process on port 5000 with ss -tlnp | grep 5000 and stop it. (3) Permission error on the working directory — the service user must own the project folder.
pi-tx.local does not resolve — browser shows "site not found" or connection refused
First confirm the pi-tx service is running (systemctl status pi-tx). If running, mDNS (Avahi) may not have propagated yet — wait 60–90 seconds after boot and try again. As a fallback, find the Pi's IP address with hostname -I run on the Pi and navigate to that IP address directly in the browser. On Windows, mDNS resolution requires the Bonjour service (installed with iTunes or Apple Devices app) or a browser extension.
install.sh completes but the service is not enabled at boot
Run sudo systemctl enable pi-tx then sudo systemctl start pi-tx. If the unit file is missing, the install did not complete cleanly — re-run sudo ./install.sh from the directory containing the Pi TX files (the repository root in the standalone package).

Google Drive Authorization

Google Drive authorization URL never appears in the app after tapping Authorize
The Pi must have internet access to contact Google's OAuth server and generate the URL. Confirm the Pi can reach the internet: run curl -s https://accounts.google.com | head -5 on the Pi. If this fails, check the Pi's network connection. After connectivity is confirmed, restart the pi-tx service and try again.
Authorization URL opens and access is granted, but the app still shows "Not authorized" after returning
Token exchange may have timed out. Return to the app, navigate back to Upload → Google Drive, and tap Authorize again — the Pi generates a fresh URL each time. Ensure you complete the sign-in flow and see the Google confirmation page ("You are now signed in") before switching back to the app.
Upload to Google Drive fails with a permissions or 403 error after a previously working authorization
The stored OAuth token has expired or been revoked. Re-authorize from Upload → Google Drive → Authorize in the app. Google tokens can be revoked if your Google account password changed or if the app's access was removed from your Google account's security settings.
